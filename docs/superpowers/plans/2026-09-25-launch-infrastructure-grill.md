# Launch infrastructure — grill rulings (2026-09-25)

> Rulings from the grilling of 2026-09-25 on email, notifications, hosting, the release pipeline and the
> launch itself. Three background research lanes fed it (email providers, notification delivery, Cloudflare
> hosting); every vendor claim below was checked against a current page on 2026-09-24/25. Issues are
> created or edited on GitHub only after Alex's go-ahead on `2026-09-25-launch-issue-drafts.md`. ADR-0005
> and ADR-0010 are amended in this same change. The privacy notice draft is
> `docs/legal/politica-de-confidentialitate.md`.

## Facts established before the rulings

- `osubb.ro`: nameservers `nsa`–`nsd.xservers.ro` (cyber_folks, cPanel; Alex has DNS access). MX → Google
  Workspace. Apex SPF lists four IPs and `+a +mx` but no `include:_spf.google.com`; no DKIM at Google's
  default selector; DMARC `p=none`. `app.osubb.ro` does not exist yet. Registrant and Workspace admin
  unknown; an OSUBB GitHub organization exists but is unreachable (recovery in progress).
- Cloudflare has no organization tier below Enterprise; an _account_ is the container, renameable, with
  members and roles on every plan, and the last Super Administrator cannot be removed. Workers custom
  domains need the zone on Cloudflare; Pages accepts a sub-domain by CNAME from external DNS. Pages is
  supported with no end date; Cloudflare's docs say "start new projects with Workers"; static requests are
  free and unlimited on both. Cloudflare's Git integration deploys production on every push, so a GitHub
  Environment cannot gate it. Zero Trust Access: 50 seats free, then $7 per user per month.
- Supabase: staging (`bbhetqtmavveaoqlxjhp`, eu-central-1, created 2026-08-19) has both the legacy
  `anon`/`service_role` JWT keys and the new `sb_publishable_`/`sb_secret_` keys. Legacy keys are
  deprecated by the end of 2026. `send-push` today needs the legacy JWT (`verify_jwt = true` + a `role`
  claim check); the frontend uses the legacy anon key. The auth email rate limit is project-wide, counts
  invitations, defaults to 30/hour once custom SMTP is on, and is checked before the Send Email hook.
- The magic-link and invite templates use `{{ .ConfirmationURL }}`: the token is consumed on Supabase's
  verify endpoint before the app is reached, and the six-digit code is the same token. `stud.ubbcluj.ro`
  is on Microsoft 365, whose link scanning can consume such links. `csv-import` refuses more than 100
  rows per file, invites serially, and re-running a file skips existing profiles; `invite-member` refuses
  an existing profile (409), so no re-invite path exists.
- The repository is public under `Alex-Bancila`; no GitHub Environments exist; four secrets sit at
  repository level (`SUPABASE_ACCESS_TOKEN`, `SUPABASE_DB_PASSWORD`, `SUPABASE_PROJECT_REF`,
  `STAGING_DB_URL`) and are readable by any workflow run from a same-repo branch. Actions minutes and
  Environment protection rules are free on a public repository.
- Resend: free 100/day and 3,000/month, Pro $20/month; SMTP `smtp.resend.com:465`, user `resend`,
  password = a sending-only API key scoped to one domain; EU sending region `eu-west-1`, all logs stored
  in the US; DKIM/SPF/DMARC records live on child names, never at the sending name itself, so
  `noreply@app.osubb.ro` coexists with the hosting CNAME on `app`. Brevo (300/day, EU) was the
  runner-up; its free-plan terms could not be verified and its verification record clashes with a CNAME.
- Web Push vendors (OneSignal, FCM, Novu, Knock, Courier, MagicBell, Pusher Beams) each add a data
  processor that receives member identifiers and plaintext text, remove no per-environment step, and
  either lack an EU/DPA option on a free plan or lack iOS web push. Cloudflare has no push product.

## Launch checklist in dependency order

1. Cloudflare account, rename, 2FA, API token (Pages Edit). Resend team, domain `app.osubb.ro`, four DNS
   records at cyber_folks. New Supabase organization and production project (Pro, Frankfurt, spend cap).
2. `wrangler pages project create osubb-staging --production-branch main`. GitHub Environments `preview`
   and `staging`; move the four secrets; add variables. Merge #110. First staging deploy.
3. Staging dashboard (#54): auth settings, templates, SMTP (L5), rate limit, Site URL
   `https://osubb-staging.pages.dev`, redirects `/auth/callback` and `/auth/confirm`; from a terminal
   `ALLOWED_ORIGINS=https://osubb-staging.pages.dev`; VAPID secrets; Vault rows with the new secret key
   after L8 merges. Two curl checks from auth-config.md. One real invitation to a team address.
4. Merge #78 (Release workflow), L12 (headers), L7 (click-to-confirm), L8 (push hardening), L16 (privacy
   page). Enforce the CSP on staging after a clean Report-Only pass.
5. Production dashboard (#77): same as step 3 with production values; processor agreements accepted.
   `wrangler pages project create osubb-app`; production Environment with reviewers; production token.
6. First Release: empty database, functions, web to `osubb-app.pages.dev`; smoke checks. Add the custom
   domain in Pages, **then** the CNAME `app → osubb-app.pages.dev` at cyber_folks; certificate Active.
7. End-to-end on `app.osubb.ro`: invite Alex, click-to-confirm page, six-digit code, PWA install on Android
   and iPhone, push subscribe and one test notification, `curl` headers, Observatory.
8. Acceptance run L17 on staging. `#112 --dry-run` on staging, then the real run on production.
9. #36: invitations, quickstart with the iPhone Home Screen steps first, the privacy notice link.
